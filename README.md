# KPIBALAGANCHIKBOT

Бот клуба (v5): всё живёт в ЛС ботов (VK и TG), а сообщество ВК используется
только для двух проверок — **кто админ** (руководители из API) и **кто член
клуба** (`groups.isMember`).

Актуальный план: [docs/60-v2-plan.md](docs/60-v2-plan.md).

## Что умеет

- **События**: глава создаёт командой в ЛС бота ВК
  `/событие Название - 15.09 19:00 - 15.09 21:00 - описание` → превью →
  публикация: живые карточки в ЛС подписчикам (VK) и слинкованным (TG).
- **RSVP**: кнопки на карточке или текстом (reply на карточку —
  «пойду/возможно/не пойду/снять»); смена выбора — зачёркивание с временем.
- **Опросы**: `/опрос Вопрос` + варианты построчно, `[несколько]`,
  `[до 20.09 19:00]` (старый формат через `;` тоже работает) — тумблеры
  вариантов, одиночный/мультивыбор, авто-закрытие по сроку, итоги.
- **Управление из чата**: `/edit <id> <поля как при создании>` (алиас
  `/изменить`), `/удалить <id>` (карточки удаляются у всех), **закрыть и снова
  открыть запись/опрос** (`[🔒]`⇄`[🔓]` в панели), `/посещаемость
  <id>` (кто реально пришёл), `/экспорт` (красивый xlsx с итогами), компактные
  списки с кнопкой `[⚙️ #id]` и панелью действий (объявление, изменить,
  закрыть/открыть, отменить, итоги, удалить).
- **Лог в сообщество**: завершённые события, закрытые опросы и объявления
  публикуются постом на стене сообщества (`VK_WALL_LOG=true`).
- **Тех-уведомления**: `TECH_ADMIN_VK_PEER` — «✅ Бот запущен» и суточный
  heartbeat (время, подписки) в чат «Логи».
- **Обращения**: `[📩 Написать админам]` — релей руководителям; ответ reply'ем
  уходит участнику (многократно), остальным админам — пометка «↩️ отвечено»;
  история хранится в БД (переживает рестарт).
- **Объявления**: глобальные и по событию/опросу (секция «📢 Объявления»
  в карточке) + TTL-уведомления (48 ч, схлопываются), медиа-вложения.
- **Членство**: только члены сообщества клуба — остальным «нет доступа»;
  подписка автоматическая при первом сообщении; **академ** = исключение из
  сообщества: бот ставит паузу, карточки сняты, ничего не приходит
  (уведомление «📴»), при возврате — всё восстанавливается.
- **Синк**: руководители и членство сверяются раз в час + кнопка админа
  `[🔄 Синхронизация]` с отчётом об изменениях; админы — руководители
  сообщества из API + `ADMIN_VK_IDS`; режим админа переключается кнопкой.
- **TG**: карточки, уведомления и кнопки в ЛС слинкованным (привязка задаётся
  в ВК — ник TG в настройках); без привязки — алерт с инструкцией;
  «📩 Написать админам» — обращения в VK ЛС руководителей, ответ админа
  reply'ем уходит обратно (можно несколько раз).
- **Надёжность**: outbox с ретраями, одно pending-задание на пост, единая
  джоба актуализации карточек (подписка/публикация/голос/синк + тик 30 с),
  дедупликация постов, напоминания reply'ем на карточку, TTL-очистка
  уведомлений, батч-рассылки `user_ids` (до 100), ночной бэкап БД (7 копий).

## Установка

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt   # Windows
# pip install -r requirements.txt               # Linux/macOS
```

## Подготовка платформ

1. **ВК**: создать **частное** сообщество (участники — члены клуба) →
   «Сообщения» включить → «Работа с API»: ключ доступа сообщества (права:
   сообщения, фото, документы, менеджер) → `VK_TOKEN`; включить «Bots Long
   Poll API»; `VK_GROUP_ID` — числовой id сообщества. Руководители сообщества
   автоматически становятся админами бота.
2. **TG**: создать бота через @BotFather → `TG_TOKEN`.
3. Скопировать `.env.example` → `.env`, заполнить. `ADMIN_VK_IDS` — только
   дополнительные админы (руководители берутся из API).

Интеграционная проверка живых API:
`.venv\Scripts\python integration_check.py [--messaging]` (read-only + опциональное
самоликвидирующееся тест-сообщение админу).

## Деплой в Docker

```bash
docker compose up -d --build
docker compose logs -f
```

Полная инструкция для VPS (установка, .env, обновление, бэкапы,
troubleshooting): [docs/80-deploy.md](docs/80-deploy.md).

- **БД — в volume** `./data:/app/data` (SQLite + бэкапы переживают пересборку).
- `restart: unless-stopped`, HEALTHCHECK (`healthcheck.py`: БД открывается и
  отвечает на SELECT), лог-ротация json-file (10 МБ × 3).
- `.env` не попадает в образ (`.dockerignore`), передаётся через `env_file`.

### Как работает SQLite в контейнере

- **Один процесс, один инстанс**: SQLite — однописательная БД, горизонтально
  не масштабируется; воркеров больше одного не заводить.
- **WAL-режим**: читатели не блокируют писателя; `busy_timeout=10000`.
  При остановке (SIGTERM/SIGINT) бот делает `wal_checkpoint(TRUNCATE)` и
  закрывает движок — файл БД остаётся консистентным.
- **Гигиена роста** (важно: всё в одном volume): retention-чистка ежедневно
  (outbox-задания >30 дн., удалённые посты >7 дн., обращения >90 дн.,
  выполненные напоминания >30 дн.) + `VACUUM` по понедельникам; бэкапы — 7
  копий с ротацией.
- Медиа и отчёты **на диск не пишутся**: вложения перекачиваются в памяти,
  `/экспорт` собирает xlsx в памяти и отправляет файлом (только демо-скрипт
  пишет `demo_export.xlsx`).
- Не храните volume на сетевых ФС (NFS/SMB) — SQLite там нестабилен; обычный
  локальный диск или SSD хостинга.

## Структура (трёхзвенная: API → BLL → DAL)

```
api/    платформенные адаптеры: vk_client, tg_client, vk_handlers, tg_handlers,
        renderers, senders (outbox + рейт-лимиты)
bll/    домен: events, polls, rsvp, summary, publication, announcements,
        profiles (подписка/членство), linking, jobs (таймеры, сверка, TTL)
dal/    SQLite: models (contents, posts, polls, …), repositories, database
```

Исходящие сообщения идут через **outbox**: BLL кладёт задания, сендеры
исполняют с лимитами и ретраями — рассылки переживают рестарт.
