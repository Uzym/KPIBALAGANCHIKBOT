# 75. Большое ревью v5: нужные правки и предложения по функционалу

Ревью кода и поведения v5 (только ЛС). Разбито по приоритетам: 🔴 правки-баги,
🟠 функционал, которого не хватает, 🟢 улучшения.

## 🔴 Нужные правки (баги и риски)

### 1. Blocked-подписчик не восстанавливается
`on_member_message` обрабатывает `None/paused/stopped`, но не `blocked`
(заблокировал бота → разблокировал). После разблокировки человек пишет боту,
получает меню, но **карточки не возвращаются и рассылки не идут**.
**Правка:** ветка `blocked` → `activate_subscription` + карточки, как у `paused`.

### 2. Голос не проверяет членство
Кнопки голоса проверяют только `active`-подписку. Человек в академе
(исключён из сообщества, но синк ещё не прошёл) может голосовать по живым
карточкам до часа. **Правка:** в `vote/remove_vote/poll/poll_clear` дополнительно
`is_member_cached`; если не член — тост «Нет доступа / академ».

### 3. Сводки уходят только конфиг-админам
`notice_admins` рассылает на `cfg.admin_vk_ids`, а не на всех `app.admins_vk`
(руководителей из API). Админ-руководитель без записи в `ADMIN_VK_IDS` не
получит «🏁 Завершено» и «🔒 Опрос закрыт». **Правка:** прокидывать `admins`
(множество) в `close/cancel/finish` и `notice_admins` (jobs/handlers передают
`app.admins_vk`).

### 4. Место (place) нельзя задать
Поле есть в модели и рендере, но ни `/событие`, ни `/edit` его не принимают
(парсер создания не знает «место»). **Правка:** поддержать `место=Зал №2`
в команде создания и в `/edit` (или сегмент `📍 Зал №2`), плюс очистка.

### 5. «Твой ответ» в списках участника
Планировалось, но `listing_text` не принимает аккаунт — участник не видит свой
текущий голос в «📅 События»/«🗳 Голосования». **Правка:** `listing_text(s, cfg,
account_id=None)` + строка «твой ответ: ✅».

### 6. Нельзя очистить поля через /edit
- Событие: описание нельзя сбросить (пустое поле игнорируется), место — аналогично.
- Опрос: срок можно только поставить/сдвинуть, нельзя убрать.
**Правка:** поддержать `описание=-` / `до без срока` (или `до -`).

### 7. TG-блокировка бота не помечается
Если слинкованный TG-юзер заблокировал бота, его dm-задания ретраятся 5 раз
и падают в failed на каждое уведомление (шум и трата попыток).
**Правка:** при TG-ошибке «blocked» ставить `account.tg_dm_notifications=false`
(или отдельный флаг) + один раз уведомить админа.

### 8. Кэш членства задерживает «нет доступа»
`membership_cache` (10 мин) может дать академ-человеку доступ в течение
10 минут после исключения. Некритично (синк чистит кэш), но для аккуратности:
**правка** — при `paused`-статусе в подписке не доверять кэшу `True`, всегда
свежая проверка.

## 🟠 Функционал, которого не хватает

### 9. Отметка «кто реально пришёл» + статистика
После завершения события админ жмёт «📊 Кто пришёл» → бот присылает список
«✅ Придут» с кнопкой на каждого → собирает факт посещения. Дальше:
`/статистика` — кто сколько раз был/записывался по месяцам. Закрывает старый
открытый вопрос из PLAN и даёт клубу реальную пользу.

### 10. Повторяющиеся события (тренировки)
Клубу нужны регулярные события: `/событие Тренировка - вт 19:00 - 21:00 -
описание - повтор=4` (или `каждую неделю до 30.09`) — бот создаёт серию
черновиков/событий со ссылкой «часть серии». Большая фича, можно этапом.

### 11. Отчёт о доставке публикации
Сейчас глава видит «ЛС N, доставка в прогрессе» — и всё. Нужен финальный отчёт:
«Разослано X/Y; не дошло: Аня (заблокировала бота)». **Как:** publish помечает
batch id; каждый успех/фейл dm-задания учитывается; по нулю pending — отчёт
админу. (Косвенно блокирует и п.7 — видно, кто недостижим.)

### 12. `/удалить <id>` (полное удаление контента)
Сейчас только отмена (карточки остаются с [ОТМЕНЕНО]). Для ошибок/дублей
нужно удаление: карточки удаляются у всех (`messages.delete` через outbox),
запись и голоса — из БД. Плюс чистка черновиков старше N дней и команда
`/черновики`.

### 13. Экспорт CSV
`/экспорт` — итоги событий/опросов в CSV (событие, дата, списки придут/
возможно/не придут) — админу файлом в ЛС.

### 14. Heartbeat и уведомление о падении
Лог-строку heartbeat (раз в N минут) + при старте бота сообщение админам
«Бот запущен». Падение ловится внешне (Task Scheduler/NSSM), но «запустился
после ребута» в ЛС — полезно.

### 15. `/help` и `/черновики` команды
Справка сейчас только кнопкой; добавить `/help` (и `/помощь`). Список
черновиков — из п.12.

## 🟢 Улучшения

### 16. Ссылка на сообщество в «Нет доступа»
«🔒 Нет доступа: бот только для участников сообщества клуба» + ссылка на
сообщество (новичку понятно, куда вступать). Спорно по «информация только
внутри контура» — но ссылка не раскрывает контент. На усмотрение.

### 17. Персист обращений
Маппинг «пересланное сообщение → участник» живёт в памяти; после рестарта
ответы админа на старые пересылки перестают доходить. Перенести в таблицу
`appeals` (id, cmid, platform, member_id, created_at) — заодно появится история.

### 18. Батч-отправка VK `user_ids`
Для plain-уведомлений (без персональных reply_to) можно слать до 100 адресатов
одним вызовом (`user_ids`) — рассылка в разы быстрее. Карточки остаются
персональными (отдельные send).

### 19. Подтверждение «событие в прошлом»
При создании события в прошлом — предупреждение в превью («⚠️ Событие в
прошлом — уверен?»).

### 20. Тост с текущим выбором в TG
В TG-ЛС карточка персональная (можно подсвечивать выбор на кнопках, как в VK,
или тостом «Твой выбор: 1, 3») — сейчас тостов о выборе нет.

### 21. Пометить docs/10–50 устаревшими
Доки v1–v2 (мост, беседа, темы) устарели. Добавить в их шапки «исторический
документ, актуально: docs/60, docs/70».

### 22. Резервное копирование БД
Ночная копия `data/kpibalaganchikbot.db` (ротация 7 штук) — из старых планов, дёшево и
защищает от потери данных.

## Что уже хорошо (не трогаем)

- Outbox с ретраями и одним pending-заданием на пост; дедуп постов (unique index).
- Живые карточки (edit на месте, live проверено), TTL-очистка (delete, live
  проверено), схлопывание уведомлений.
- Сквозной `#id`, `/edit <id>`, панели `[⚙️]`, режимы админа, справки.
- Членство/академ с авто-подпиской и уведомлениями «📴/👋», синк раз в час +
  кнопка `[🔄 Синхронизация]`.
- Линковка однонаправленная, имена из ВК, TG-алерт, обращения с ответами reply.
- 58/58 тестов, интеграционный скрипт с живыми проверками.

## Ревью №2: находки после внедрения (все исправлены)

1. **Ретрай `vk_bulk` задваивал рассылку** — при повторной попытке задания
   рассылка уходила всем адресатам заново. Теперь уже доставленные
   (`post.ok` + message_id) отфильтровываются перед отправкой.
2. **`attend` падал при пустом payload** (`int(""[2:])`) — добавлен guard.
3. **`user_ids` устарел в VK API 5.138** (живой тест: error 100 «deprecated»).
   Батч переведён на **`peer_ids`** (до 100, только для ключа сообщества) —
   live round-trip зелёный.
4. **`docs.save` требовал строку `file` как есть** (живой тест: «file field is
   incorrect» при передаче dict/повторном дампе). Исправлено — live round-trip
   «upload_doc → attach → delete» зелёный; заодно проверен путь `/экспорт`.
5. **Артефакты посева демо-данных**: повторный запуск дублировал контент, а
   голоса по уже закрытому опросу молча не проходили (порядок в seed). Демо-БД
   теперь пересоздаётся начисто, порядок посева исправлен.
6. В интеграционный скрипт добавлены два новых самоликвидирующихся live-теста:
   батч-рассылка и загрузка документа; написан `seed_demo.py` (синтетика +
   аналитика + экспорт xlsx) и тест аналитики на посеянной БД.
