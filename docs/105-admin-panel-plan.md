# 105. Админ-панель: план (v6.2) — домен + Caddy + NiceGUI

Задача: панель управления ботом с телефона и с компьютера, полный функционал.
Решения владельца: Telegram не подходит (в РФ заблокирован); **домен купить
можно**; VPN/Tailscale — нет; возиться с системой логинов/паролей — нет.
Бот живёт на VPS в Docker, один Python-процесс.

## Итоговый выбор

**Панель на NiceGUI (Python-интерфейс, Quasar) в процессе бота + купленный
домен + Caddy с авто-HTTPS.** Авторизация — **«вход по одобрению»**: без
паролей; человек открывает панель → админам в ВК приходит «попытка входа» с
кнопками ✅/❌ → после одобрения выдаётся API-токен.

- Домен: любой (`.ru` — дёшево, ~200–500 ₽/год). Поддомен `panel.<домен>` →
  A-запись на IP VPS.
- Caddy на VPS: `panel.<домен>` → `127.0.0.1:8080`, Let's Encrypt сам.
- Панель слушает только `127.0.0.1:8080` (наружу только Caddy).
- Никаких туннелей/интерстишлов: свой домен, свой TLS.

## Почему NiceGUI (готовые Python-решения)

Сравнение вариантов интерфейса:

| Решение | Что это | Плюсы | Минусы |
|---|---|---|---|
| **NiceGUI** ⭐ | Python-фреймворк на Quasar/Vue | Весь UI на Python (таблицы, формы, диалоги, тосты — готовые); адаптивен на мобиле из коробки; зрелый и активно развивается | FastAPI/uvicorn внутри — запускается отдельным потоком в нашем процессе; UI-тонкости (кастомные раскладки) — через его API |
| htmx + aiohttp + Jinja2 + Pico.css | серверный рендеринг без фреймворка | Минимум новых зависимостей; тот же цикл; полный контроль HTML | Весь HTML/CSS руками; мобильную адаптацию делать самому |
| PyWebIO | Python-формы/таблицы | Прост; умеет aiohttp | UI бедноват для полноценной панели |
| Streamlit / Dash | дашборды | Быстро для графиков | CRUD-панель и мобильный UX — не их конёк; авторизация костылями |
| Reflex / Flet | «Flutter на Python» | Красиво | Тяжёлые, своя инфраструктура, оверкилл |

**Решение: NiceGUI.** Вся логика панели — синхронные BLL-функции (они у нас
такие), уведомления уходят через outbox (тоже синхронно ставит задачи), БД —
та же SQLite (SQLAlchemy движок потокобезопасен, WAL). Единственная правка
существующего кода: действия панели, которым нужно сообщение в VK/TG
(например, одобрение заявки TG), маршрутизируются через outbox — тогда
панель не трогает event loop бота вообще. NiceGUI запускается потоком
рядом с основным циклом (один контейнер, одна БД).

## Авторизация: «вход по одобрению»

1. Открыл `https://panel.<домен>` → экран входа: подпись «кто ты»
   (необязательно) + кнопка **«Запросить доступ»**.
2. Сервер создаёт заявку (`panel_sessions`, `pending`), запоминает
   IP/User-Agent. **Rate-limit**: с одного IP не чаще одной заявки в минуту.
3. Бот шлёт всем админам (мемоизированный список, v6.1) в ВК:
   «🔐 Попытка входа в панель: <подпись> · IP <…> · <время>» + кнопки
   **[✅ Одобрить] [❌ Отклонить]** (механизм как у заявок TG).
4. ✅ — сервер генерирует токен (`secrets.token_urlsafe(32)`), хранит хеш,
   заявка → `approved`; страница получает токен, кладёт в localStorage.
   Поздние админы видят «↩️ уже обработано». ❌ — `denied`.
5. Все запросы — `Authorization: Bearer <токен>` (или cookie); посторонние —
   401. Журнал входов/отказов — в «Логи»; `/панель` в боте — список токенов,
   `/панель отозвать <id>`.

Миграция **v5**: `panel_sessions` — id, token_hash (NULL до одобрения),
label, ip, ua, status (`pending|approved|denied|revoked`), created_at,
approved_by, approved_at.

Резерв: секретный путь `PANEL_SECRET` из `.env` (владельцу, если бот лежит).

## Интерфейс: страницы и полный функционал

Навигация: на компьютере — сайдбар слева; на телефоне — выдвижное меню/
нижние табы; таблицы на мобиле — карточками или горизонтальной прокруткой;
все действия крупными кнопками.

1. **Вход** — экран «Запросить доступ» (см. выше).
2. **Дашборд** — счётчики: активные события/опросы, подписчики по статусам,
   должники и сумма долгов; ближайшие события; свежие заявки TG (кнопки
   ✅/❌ прямо здесь); долги выше порога с ⚠️.
3. **События** — список с фильтрами (активные/закрытые/завершённые/отменённые);
   **создать** формой (название, даты/время, место, описание — тот же парсер,
   что в чате) с превью; карточка события: списки «пойдут/возможно/нет»,
   действия — закрыть/открыть запись, отменить, итоги, удалить, объявление;
   **посещаемость** — чекбоксы «пришёл» по списку.
4. **Опросы** — список; создать формой (вопрос, варианты, мультивыбор,
   дедлайн); карточка: результаты по вариантам со счётчиками, закрыть/
   открыть/отменить/удалить/итоги/объявление.
5. **Люди** — таблица: имя (переопределяемое), VK/TG, статус подписки
   (академ/бан/выключен), долг, платформы; действия: переименовать, история
   оплат, бан/разбан TG, смотреть линковку VK↔TG.
6. **Оплата** — таблица долгов с ⚠️-порогом; **внести платёж** (автокомплит
   «кто» — тот же поиск по имени/логину/id, что в чате; сумма; за что);
   корректировки; история операций по человеку.
7. **Заявки TG** — очередь pending с ✅/❌; журнал принятых/отклонённых.
8. **Объявления** — создать глобальное или по событию/опросу (текст;
   медиа — v1 нет, в чате остаётся).
9. **Экспорт** — скачать xlsx (`/экспорт`-сборка); там же кнопка «выгрузить
   в Google Таблицы» — если позже подключим.
10. **Доступы** — активные токены (подпись, IP, дата), отозвать; история
    входов. (У владельца.)
11. **Статус** — read-only: версия, время последнего heartbeat, счётчики
    outbox-задач, время последнего синка членства.

## Фазы

1. ~~Каркас~~ ✅ — `web/panel_ui.py`: NiceGUI в потоке процесса бота
   (`ui.run` на 127.0.0.1), конфиг `PANEL_PORT`/`PANEL_SECRET`; smoke-тест
   всех страниц (local_tools/panel_smoke.py).
2. ~~Вход по одобрению~~ ✅ — миграция v5 (`panel_sessions`), `bll/panel.py`
   (заявка + токен сразу клиенту, в БД только хеш; rate-limit по IP),
   кнопки ✅/❌ у админов (action `panel_req`), `/панель` и
   `/панель отозвать <id>` в боте, журнал в «Логи»; юнит-тесты.
3. ~~Страницы~~ ✅ — дашборд, события (+создание формой, действия,
   посещаемость), опросы (+создание формой, итоги, действия), люди
   (имя/бан/история), оплата (платёж с выбором «кто»), заявки TG
   (одобрить/отказать), объявления, экспорт xlsx, доступы (отзыв), статус.
4. **Домен + Caddy** — покупка домена, A-запись `panel.<домен>` → IP VPS,
   Caddy с авто-TLS и `reverse_proxy 127.0.0.1:8080` (см. ниже), ссылка на
   панель в «Логи»; прогон на телефоне.
5. **Релиз** — обновить гайд/доки, деплой релиз-скриптом, live-проверка
   входа по одобрению с телефона.

## Caddy на VPS (фаза 4)

```bash
sudo apt install -y caddy
sudo nano /etc/caddy/Caddyfile
```

```
panel.<твой-домен> {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy   # сертификат Let's Encrypt выпустится сам
```

В `.env` на VPS: `PANEL_PORT=8080` (наружу порт не открывается — Caddy
ходит в localhost). Вход владельца без ожидания одобрения:
`https://panel.<домен>/login?key=<PANEL_SECRET>`.

## Риски и запасные пути

| Риск | Запасной путь |
|---|---|
| С сертификатом/портами что-то не так | Caddy TLS-ALPN через 443; временно self-signed |
| Домен не купили сразу | Фазы 1–4 не зависят от домена; временно Cloudflare Quick Tunnel |
| NiceGUI не зашёл (зависимости/UI) | План Б: htmx + aiohttp + Jinja2 (тот же бэкенд-слой) |
| Спам заявками на вход | Rate-limit по IP + подпись; админы отклоняют |
| Токен утёк | `/панель отозвать <id>`; токены — только хешами |
| Всё веб-недоступно | бот-команды в чате работают как раньше; Google Таблицы — резерв |

## Что НЕ делаем

Не плодим отдельные сервисы/БД (панель — слой над BLL и той же SQLite).
Не делаем форму логина с паролями (одобрение админом). Не выставляем порт
панели наружу (только 127.0.0.1 + Caddy). Не тащим медиа-загрузку в панель
v1 (текст-объявления; фото — по-прежнему из чата).
