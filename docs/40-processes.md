# 40. Процессы, жизненный цикл, шаблоны, правила

> ⚠️ Исторический документ (v1–v2). Актуально: [docs/60-v2-plan.md](60-v2-plan.md).

## 1. Подписка и профили

### 1.1 Подписка VK

```
/start → [Присылать события][Не присылать]
  → SubscriptionService.validate(): состоит ли в беседе (getConversationMembers)
     ├─ да  → active; прислать все активные события (dm_card)
     └─ нет → guest; инструкция со ссылкой на беседу
Ревалидация: раз в сутки + при каждом RSVP
  active → (вышел) → paused + уведомление → (вернулся, кнопка/ревалидация) → active
Ошибка доставки ЛС → blocked (видно в /подписчики)
Авто-подписка: голос кнопкой на записи в беседе (если spike ок)
  → создаётся active-подписка + ЛС «Записал. Буду присылать события (/стоп)»
```

### 1.2 Профиль VK (в ЛС бота, [Настройки])

- «Присылать объявления» — да/нет (да по умолчанию).
- «Мой ник в TG» — @username; используется LinkingService.

### 1.3 Профиль TG (в ЛС TG-бота)

- «Моя ссылка/ник ВК» — vk.com/…; настроки объявлений нет (контент в общий канал).

### 1.4 Линковка аккаунтов (дедуп людей)

```
Источник данных: accounts.tg_nick (заявил VK-юзер) ↔ accounts.username (фактический TG)
                 accounts.vk_nick (заявил TG-юзер)  ↔ accounts.platform_user_id/screen ВК
Матчинг: при каждом изменении профиля и при каждом голосе с другой платформы.
Найден один матч → общий person_id → голоса сливаются, записи пересчитываются.
Ноль матчей → молча ждём (метки [VK]/[TG] в списках).
Конфликт (>1 кандидат, ник заявлён дважды) → флаг админу → /связать vk_id tg_id.
TG-аккаунт без username → только ручная связка.
Ник сменился → человек обновляет профиль, матчинг переигрывается.
```

## 2. Жизненный цикл события

```
                 /событие + [Опубликовать]
   draft ────────────────▶ active ────(глава [Закрыть запись] или авто: начало)───▶ closed
                              │                                                            │
                              ├─(глава [Отменить])──▶ cancelled                        авто:
                              │                        + отдельные реплаи              ends_at
                              │                        «❌ Отменено»                    │
                              └─(редко: отмена после закрытия — тоже cancelled)         ▼
                                                                                       finished
                                                                              + финальная сводка (отдельные сообщения)

active:   кнопки работают, записи/карточки обновляются на каждый голос
closed:   кнопки сняты, голоса заморожены; событие ещё видно (можно читать списки)
cancelled: таймеры сняты, записи помечены, голоса заморожены
finished: финальная сводка: придут/возможно/не придут + имена; событие в архиве
```

Таймеры (scheduler): напоминания (за 24 ч, за 2 ч), авто-закрытие записи (правило
из конфига, дефолт — в момент начала), авто-завершение (ends_at + 5 мин).

## 3. Создание события

```
Команда: /событие Название - начало - конец - описание
Форматы начала/конца: 15.09 19:00 · 15.09.2026 19:00 · сегодня 19:00 · завтра 18:00 ·
                      вт 19:00 (ближайший следующий вторник) · 19:00 (сегодня/завтра)
Правила:
  - разделитель « - » (минимум один пробел с двух сторон); полей 1–4, всё кроме
    названия опционально;
  - конец по умолчанию = начало + 1 ч; конец ≤ начала → переспрос;
  - таймзона клуба (конфиг); событие в прошлом → подтверждение;
  - любое непонятое поле → бот переспрашивает только его (черновик не выбрасывается).
Результат: draft + превью [Опубликовать][Изменить поле][Отмена].
```

## 4. Публикация (fan-out)

```
publish(event):
  1. event.status=active
  2. outbox: dm_card → все active-подписки VK
             feed_record → общая беседа VK (+ кнопки*, spike)
             topic_record → TG-тема «События» (inline-кнопки)
  3. reminders: (24ч, 2ч), авто-закрытие, авто-финиш
  4. отчёт главе: «Разослано N/M; не дошло: …»
Senders исполняют с рейт-лимитами; message_id фиксируются в event_posts.
Подписался позже → при подписке сразу dm_card всех active-событий.
```

## 5. RSVP

```
vote(event, account, answer):
  проверки: event.status=active, запись не закрыта, подписка не guest/paused
            (голос из беседы → авто-подписка)
  DAL: upsert votes: prev_answer=старый, answer=новый, changes_count++, updated_at=now
  SummaryBuilder:
    dm_card VM (ЛС подписчика): чистые текущие списки
    feed_record/topic_record VM: списки + зачёркнутые изменившие с временем
  outbox: edit всех dm_card, edit feed_record, edit topic_record
Senders: edit с debounce (VK ≥3 с на одно сообщение), vm_hash — без изменений не шлём.
Латеральное: нажатие «снять ответ» → голос удаляется, имя просто исчезает из списков.
```

## 6. Изменение события

```
reply на сообщение события + /изменить поле=значение  (или визард по кнопке)
Поля: название, начало, конец, место, описание.
Действия:
  - edit всех записей и карточек (актуальные поля)
  - отдельные сообщения «⚠️ Изменение события: <что именно поменялось>»
    (ЛС подписчикам, реплаи на запись в беседе и TG-теме)
  - пересчёт таймеров напоминаний/авто-закрытия/финиша
Правило: смена времени — всегда с уведомлением сообщением (edit можно не заметить).
```

## 7. Объявления

```
reply на сообщение события + текст (+ медиа)   // явная форма: /объявление текст
Действия:
  - отдельное сообщение-реплай на запись в беседе VK
  - отдельное сообщение-реплай на запись в TG-теме «События»
  - ЛС VK-подписчикам с send_announcements=true («📢 [Событие] текст»)
Медиа: фото/видео/документы/голосовые — переносятся между платформами.
```

## 8. Закрытие записи / отмена / завершение

```
Закрытие записи (глава: reply → [Закрыть запись]; авто: по правилу из конфига):
  - edit записей/карточек: кнопки заменены строкой «🔒 Запись закрыта»
  - отдельный реплай в беседе и TG-теме: «🔒 Запись закрыта. Придут N, возможно M»
  - голоса после закрытия не принимаются (тост «запись закрыта»)

Отмена (глава: reply → [Отменить]):
  - отдельные реплаи «❌ Событие отменено» (беседа + TG-тема) + ЛС всем подписчикам
  - edit записей: первая строка получает пометку [ОТМЕНЕНО]
  - таймеры сняты; поздняя отмена (после closed) — то же самое

Завершение (авто по ends_at):
  - отдельные реплаи-сводки в беседе и TG-теме:
    «🏁 Завершено: «Тренировка». Придут 5: имена…; Возможно 1: …; Не придут 2: …»
  - ЛС главе с той же сводкой; кнопки сняты, статусы updated
```

## 9. Напоминания

```
За 24 ч и за 2 ч (конфиг):
  - ЛС VK-подписчикам: «⏅ Через 2 часа — Тренировка. Придут N» + карточка-ссылка
  - реплай в TG-теме на запись
Не дублируем, если событие отменено/завершено; отметка done в reminders.
```

## 10. Мост-обсуждалка

```
Пары: беседа#1 ↔ тема#1, беседа#2 ↔ тема#2 (конфиг chats).
VK→TG: message_new (peer = беседа) — пропустить: свои (from_id=-group),
       зеркала (bridge_map), стикеры/сервисные.
       Нормализация: текст, медиа (скачать → MediaService), reply (развернуть),
       пересылки (развернуть с «↪ от»).
       VM «👤 [VK] Имя: …» → outbox (tg topic).
TG→VK: симметрично, подпись «👤 [TG] Имя: …».
Имена: кэш accounts.display_name; обновляется при новых сообщениях.
Медиа-фолбэки: TG-файл >20 МБ → ссылка; видео-«видеозапись» ВК → ссылка.
Edit/delete пользователей в мосте — этап 2 (сначала только новые сообщения).
```

## 11. Фоновые задачи (scheduler)

- раз в минуту: авто-закрытия, авто-завершения, напоминания по расписанию;
- outbox-ретраи: постоянно (next_attempt_at), ночь — повтор failed;
- ревалидация подписок: раз в сутки ночью;
- чистка media_cache: файлы старше 7 дней.

## 12. Шаблоны сообщений

### 12.1 Запись события (беседа VK / TG-тема «События») — живое сообщение

TG (MarkdownV2):

```
📋 Тренировка
📅 Пн 15.09, 19:00–21:00 · 📍 Зал №2
Спарринг, взять перчатки.

✅ Придут (3): Аня, Вика, Гоша
🤔 Возможно (1): Дима
❌ Не придут (1): Ева, ~~Боба~~ (был ✅, изменил 19:40)

[✅ Приду] [🤔 Возможно] [❌ Не приду] [Снять ответ]
```

VK (нет markdown): зачёркивание юникодом `Б̶о̶б̶а̶` (spike; fallback —
пометка «(был ✅, изм. 19:40)» без зачёркивания).

Статусы в записи (первой строкой): `[ОТМЕНЕНО] ❌`, `🔒 Запись закрыта`,
`🏁 Завершено`.

### 12.2 Карточка ЛС подписчика VK — живая, чистые списки

Спарринг, взять перчатки.

🤔 Возможно (1): Дима

## 13. Правила и краевые случаи

- **Зачёркивание в VK**: юникод-комбинирование (U+0336) — проверить рендер на
  клиентах (spike); fallback — текстовая пометка. TG — нативный `~~…~~`.
- **Длинные списки**: сообщение ≤4096 символов; при переполнении — первые N имён
  + «…и ещё K (полный список у бота в ЛС: /события N)».
- **Edit rate**: VK — debounce ≥3 с на сообщение, не чаще ~1 edit/с на чат;
  без изменения контента (vm_hash) edit не шлётся.
- **Edit упал** (сообщение удалено) → event_posts.status=deleted → следующий
  апдейт новым сообщением.
- **Подписался после анонса** → сразу все active-события.
- **Голос после закрытия записи** → тост «Запись закрыта», голос не меняется.
- **Двойное нажатие** → идемпотентность по (user, message, action).
- **Один человек, два неслинкованных аккаунта** → две строки с метками [VK]/[TG];
  после линковки записи пересчитываются автоматически.
- **Медиа-лимиты**: TG-файл >20 МБ и нескачиваемые видео ВК → ссылка вместо файла.
- **Таймзона**: одна на клуб (конфиг, дефолт Europe/Moscow); в БД — UTC.
- **Мост**: зеркало на зеркало не отвечает (bridge_map), бот свои сообщения
  не зеркалит (они и так публикуются нативно с обеих сторон).
