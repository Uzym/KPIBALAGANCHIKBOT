# 50. Этапы, spike-проверки, риски, открытые вопросы

> ⚠️ Исторический документ (v1–v2). Актуально: [docs/60-v2-plan.md](60-v2-plan.md).

## 1. Этапы разработки

### Этап 0 — spike (~1 день)

Проверить на живых сообществе/группе/ботах, результаты фиксировать в этом файле:

1. **VK: бот в беседе** — бот-сообщество добавлен в чат, включены «Сообщения из
   бесед» → приходят все `message_new` с корректным `from_id`.
2. **VK: callback-кнопки в беседе** — `message_event` от пользователя, который
   не начинал диалог с ботом (нужно для кнопок на записи и авто-подписки).
   Если нет — кнопки только в ЛС.
3. **VK: зачёркивание** — рендер юникод-зачёркивания (U+0336) в веб/мобильных
   клиентах. Если плохо — текстовый fallback.
4. **VK: `messages.edit`** — темп редактирования одного сообщения (debounce),
   сохранение клавиатуры при edit.
5. **VK: `getConversationMembers`** — список участников беседы от токена
   сообщества (валидация подписок).
6. **TG: форум-темы** — постинг в тему (`message_thread_id`), inline-кнопки,
   edit сообщения с кнопками, MarkdownV2 strike.
7. **Медиа-круг**: фото/документ/голосовое VK→TG и TG→VK; лимиты (20 МБ getFile).
8. **Rate limits** рассылки: безопасный темп ЛС-рассылки VK (проверить на 2–3
   аккаунтах) — заложить лимиты в senders.

### Этап 1 — событийное ядро (MVP)

- Каркас: API/BLL/DAL скелет, конфиг, БД + миграции, outbox + senders, планировщик.
- Профили/подписки VK: /start, валидация членства, настройки (объявления, TG-ник),
  авто-подписка из беседы (если spike п.2 ок), ревалидация.
- События: команда создания + превью, публикация (fan-out), живые записи
  (беседа + TG-тема) и карточки ЛС, RSVP с историей и зачёркиваниями,
  изменения, объявления (реплаи + ЛС по настройке), закрытие/отмена/завершение
  (включая авто), напоминания, админ-команды, линковка по никам.
- TG-тема «События»: записи с inline-кнопками, голоса, реплаи.

### Этап 2 — мост-обсуждалка

- Пары беседа↔тема, зеркалирование текста/медиа/reply/пересылок, bridge_map,
  защита от циклов, медиа-фолбэки.
- (Опция) зеркалирование edit/delete пользовательских сообщений.

### Этап 3 — обвязка

- Google Calendar (создание/обновление события, ссылка в записи).
- Отметка факта посещения (кнопка главы «кто реально пришёл») и статистика
  посещаемости по людям/периодам.
- Экспорт итогов (CSV), возможно мини-веб-панель.

## 2. Риски и меры

| Риск | Мера |
|---|---|
| Callback-кнопки в беседе VK не работают у неподписанных | Fallback: кнопки только в ЛС; запись в беседе информационная |
| Юникод-зачёркивание криво рендерится в VK | Текстовая пометка «(был ✅, изм. 19:40)» |
| Edit-лимиты VK при частых голосах | Debounce, vm_hash, батчинг изменений (5 c) |
| Ники меняются / не совпадают → дубли людей | Ручная `/связать`, напоминание обновить профиль, метки платформ в списках |
| TG-файлы >20 МБ, видео ВК | Фолбэк ссылкой |
| Рассылка упирается в лимиты VK | Outbox с лимитами и ретраями; отчёт главе |
| Один процесс — единая точка отказа | Автоперезапуск, outbox переживает рестарт, heartbeat-лог |
| Бот заблокирован участником | Статус blocked, /подписчики, глава оповещает лично |
| VK API меняется | Фиксация версии API, обновление vkbottle осознанно |

## 3. Открытые вопросы

1. **Авто-закрытие записи**: в момент начала события (дефолт) или за N часов?
2. **Напоминания**: за 24 ч и за 2 ч — ок? Нужно ли третье (утро дня события)?
3. **Факт посещения**: нужна ли отметка «кто реально пришёл» (этап 3, для статистики)?
4. **Зачёркивание в VK**: юникод или сразу текстовая пометка (решит spike).
5. **Хостинг**: ваш ПК (постоянно включён?) или VPS — влияет только на деплой.
6. **Google Calendar**: клубный аккаунт есть? Нужен ли вообще (этап 3)?
