# 85. Админ-панель: как сделать удобно, без домена и авторизации

Чат-администрирование (команды + кнопки) хорошо для быстрых действий, но для
«создать событие с полями», «отметить пришедших», «посмотреть всё сразу» —
неудобно. Предлагаю лёгкую локальную веб-панель в том же контейнере.

## Критерии

- ❌ без домена/DNS/TLS-сертификатов;
- ❌ без системы аккаунтов и паролей;
- ✅ один процесс, минимум новых зависимостей;
- ✅ работает откуда угодно (с телефона тоже).

## Варианты доступа (одна и та же панель, разные способы зайти)

### A. Локальная панель + SSH-туннель (рекомендую)

Панель слушает **только localhost:8080** внутри VPS — снаружи её не видно
вообще. Заходишь туннелем, авторизация = твой SSH-ключ (он уже есть):

```bash
ssh -L 8080:127.0.0.1:8080 user@vps
# в браузере: http://localhost:8080
```

- Ноль новых компонентов: ни домена, ни пароля, ни открытых портов.
- Безопасность «из коробки»: кто не имеет SSH-доступа к VPS — не видит панель.

### B. Tailscale (если хочется без команды в терминале)

Ставишь Tailscale на VPS и на ноутбук/телефон → панель слушает
`tailscale0:8080`, заходишь по `http://100.x.y.z:8080` из любой сети.
Авторизация = твой tailnet (тоже без паролей). Чуть больше установки,
зато удобно с телефона.

### C. Наружу по IP + токен (если VPS не под рукой)

Панель слушает `0.0.0.0:8080`, в `.env` — `ADMIN_PANEL_TOKEN` (длинная
строка), доступ: `http://IP:8080/?token=...`. Без домена, но порт открыт
в интернет — наименее безопасный вариант, только как запасной.

## Что внутри панели (экраны)

Один лёгкий HTML (без SPA-фреймворков, минимум JS-fetch) + JSON-API:

1. **Дашборд** — активные события/опросы с счётчиками, подписки по статусам,
   очередь outbox (сколько pending/ошибок), последние записи лога.
2. **События** — список (все статусы), создание формой (название, даты с
   подсказками «завтра 19:00», место, описание), редактирование, закрыть/
   открыть, отменить, итоги, **отметить пришедших галочками**, удалить.
3. **Опросы** — создание (вопрос, варианты списком, мультивыбор, срок),
   закрыть/открыть/удалить, итоги.
4. **Объявления** — глобальное и по событию/опросу (текст; медиа — ссылкой,
   полноценная загрузка файла — позже).
5. **Люди** — подписчики со статусами (active/paused/blocked/stopped),
   линковки VK↔TG, кнопки «синк» и «связать вручную».
6. **Экспорт** — кнопка «скачать xlsx» (тот же генератор, что у /экспорт).

Всё это вызывает те же BLL-функции, что и чат: карточки у участников
обновляются, уведомления уходят — панель ничего не дублирует.

## Технически

- **aiohttp уже в зависимостях** — веб-сервер будет ещё одной asyncio-задачей
  в `app.run()` (тот же event loop, та же БД — WAL позволяет).
- Конфиг: `ADMIN_PANEL=on|off`, `ADMIN_PANEL_HOST=127.0.0.1` (или tailscale IP),
  `ADMIN_PANEL_PORT=8080`, `ADMIN_PANEL_TOKEN=` (пусто = только локальный доступ).
- Логи для дашборда — кольцевой буфер в памяти (последние 200 строк).
- Безопасность по умолчанию: если хост не указан явно — слушаем только
  localhost; compose порт наружу **не пробрасываем** (туннель сам достучится).

## Что НЕ предлагаю и почему

- **TG/VK Mini Apps** — нужны публичный HTTPS-URL и настройки платформ
  (домен, валидация) — то, от чего уходим.
- **Полноценная админка с аккаунтами** (Flask-Admin и т.п.) — перебор для клуба.
- **Portainer/Coolify** — управление контейнерами, а не ботом.

## План внедрения (если берём вариант A)

1. `api/webpanel.py`: aiohttp-сервер (static HTML + /api/* JSON), кольцевой
   буфер логов, guard по host/token.
2. Подключить BLL-эндпоинты (события, опросы, люди, объявления, экспорт,
   синк) — обёртки над существующими функциями.
3. Задача в `app.run()`, конфиг-ключи, compose без внешнего порта.
4. Тесты API (aiohttp test client) + инструкция в docs/80 (туннель,
   Tailscale, токен).
