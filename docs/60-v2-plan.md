# 60. План v5: чисто ЛС-модель (финал)

Бот-центричная модель без публичных поверхностей: **всё живёт в ЛС ботов**
(VK и TG). Сообщество ВК используется только для двух проверок: **кто админ**
(руководители из API) и **кто член клуба** (`groups.isMember`).

Стена ВК и TG-канал убраны: ограничение API (wall.edit/getById/delete — только
пользовательский токен, error 27) делает стену «одноразовой», поэтому вся
живость — в ЛС, где сообщения редактируются без ограничений.

## 0. Ключевые решения

| Вопрос | Решение |
|---|---|
| Публичные поверхности | Нет: карточки, объявления, голоса, уведомления — только в ЛС ботов |
| Сообщество ВК | Только: руководители → админы (`groups.getMembers filter=managers`), членство (`groups.isMember`) |
| Проверка членства | Вхождение в частное сообщество; без одобрения админом |
| Админы | Руководители сообщества (обновление раз в сутки) + `ADMIN_VK_IDS` |
| **id карточек** | Сквозной id (события + опросы), текстом первой строкой карточки |
| Редактирование | `/edit <id> <поля как при создании>` — из любого места чата |
| Голосование | Кнопки на живой карточке в ЛС + текстовый fallback (reply на карточку) |
| Объявления по событию/опросу | Секция «📢 Объявления» в карточке + TTL-уведомления (48 ч, схлопываются) |
| TG | Карточки/уведомления слинкованным (линковка задаётся в ВК); без линковки — алерт |

## 1. Поверхности

1. **ЛС бота ВК** — центр: участники (карточки, голоса, настройки, обращения)
   и админы (режимы, списки, панели, `/edit`, помощь).
2. **ЛС бота TG** — для слинкованных: карточки с кнопками, уведомления
   (настройка `[🔕]`), обращения к админам; статус привязки.

## 2. Сценарии

### 2.1 Участник VK

```
Пишет боту → проверка членства (groups.isMember, кэш 10 мин)
  не член → «🔒 Нет доступа: бот только для участников сообщества клуба»
  был членом (академ) → «📴 Ты в академе — вернёшься в сообщество, всё заработает»
  член → авто-подписка + сразу все активные события/опросы (карточки в ЛС)
ЛС = карточки (живые) + уведомления (объявления/изменения/напоминания)
Голосование: inline-кнопки на карточке или текстом (reply → «пойду»/«возможно»/
  «не пойду»/«снять»; опрос — «2» или «1,3»)
Настройки: объявления в личку, ник TG, отписка (/стоп), справка
Академ: админ исключает из сообщества → синк ставит paused (карточки сняты,
  ничего не приходит) + уведомление «ты в академе»; вернулся → active + карточки
```

### 2.2 Участник TG

Точка входа всегда ВК: подписка в боте ВК + ник TG в его настройках — линковка
только так. Слинкован → карточки и уведомления в TG-ЛС; нажатие кнопки голоса
без линковки → алерт:
«⚠️ Голос не засчитан. 1) Напиши боту клуба в ВК — он проверит, что ты в
сообществе. 2) В настройках укажи свой ник в TG. Имена — из ВК.»

### 2.3 Админ (VK ЛС)

```
Админы = руководители сообщества (кэш, синк раз в час) + ADMIN_VK_IDS; guard require_admin
Режимы: [🔁 Режим админа] ↔ [🔁 Режим участника]
Списки: [📋 События] / [📋 Опросы] → компактно: #id, тип, название, сроки,
  счётчики, охват + [⚙️ #id] → панель (объявление/изменить/закрыть/открыть/отменить/
  итоги/удалить; у закрытых событий — «✅ Кто пришёл»)
Редактирование: /edit <id> <поля как при создании>; /изменить — алиас
Удаление: /удалить <id> — карточки удаляются у всех участников
Посещаемость: /посещаемость <id> — отметить реально пришедших
Экспорт: /экспорт — xlsx с итогами файлом в ЛС
[🔄 Синхронизация] — ручной синк админов/членства с отчётом об изменениях
[❓ Помощь] / /help — справка админа; [❓ Как голосовать] — справка участника
Ответ на обращение: reply на пересланное сообщение — уходит участнику
  (можно отвечать несколько раз); остальным админам — пометка «↩️ отвечено»
Завершённые события/опросы и объявления публикуются постом в сообщество (архив, VK_WALL_LOG)
```

## 3. Клавиатуры

### 3.1 VK ЛС: доступ

| Кто пишет | Ответ |
|---|---|
| Не член сообщества | Текст «🔒 Нет доступа: бот только для участников сообщества клуба» (без клавиатуры) |
| Член клуба (в т.ч. вернувшийся из академа) | Авто-подписка + все активные карточки + меню участника (3.2) |
| Академ (исключён из сообщества) | Текст «📴 Ты в академе…», ничего не приходит |

Кнопки подписки нет: доступ определяется членством автоматически.

### 3.2 VK ЛС: участник (active)

Reply:
```
[📅 События]  [🗳 Голосования]
[⚙️ Настройки]  [📩 Написать админам]
```
У админа в режиме участника снизу — `[🔁 Режим админа]`.

Inline:
- Карточка события: `[✅ Приду] [🤔 Возможно]` / `[❌ Не приду] [🗑 Снять ответ]`.
- Карточка опроса: кнопки вариантов (выбранные — с ✅) + `[🗑 Снять выборы]`.
- «⚙️ Настройки»: объявления вкл/выкл, ник TG, отписка, «❓ Как голосовать».

### 3.3 VK ЛС: админ (режим админа)

Reply:
```
[➕ Событие]  [➕ Опрос]  [📢 Объявление]
[📋 События]  [📋 Опросы]  [👥 Подписчики]
[🔗 Связать аккаунты]  [🔄 Синхронизация]
[🔁 Режим участника]  [❓ Помощь]
```

Inline:
- Списки: на строку `[⚙️ #id]` → панель `[📢 Объявление] [✏️ Изменить]
  [🔒 Закрыть] [❌ Отменить] [📊 Итоги] [🗑 Удалить]` (+ `[✅ Кто пришёл]` у
  закрытых/завершённых событий).
- Все админ-действия проходят guard `require_admin`.

### 3.4 TG ЛС

Reply: не слинкован — `[📩 Написать админам]`; слинкован —
`[📅 События] [🗳 Голосования] [⚙️ Настройки] [📩 Написать админам]`.

## 4. Шаблоны

### 4.1 Карточка события (живая)

```
#12
📋 Тренировка
📅 Пн 15.09, 19:00–21:00 · 📍 Зал №2
Спарринг, взять перчатки.

✅ Придут (3): Аня, Вика, Гоша
🤔 Возможно (1): Дима
❌ Не придут (1): Ева, ~~Боба~~ (был ✅, изм. 19:40)

📢 Объявления:
• Берите перчатки и воду (пн 19:40)
```
Статусы: `🔒 Запись закрыта`, `[❌ ОТМЕНЕНО]`, `🏁 Завершено`. `#id` — первая
строка (сквозной id; TG — как хэштег).

### 4.2 Карточка опроса (живая)

```
#13
🗳 Куда идём в субботу?
Можно выбрать несколько · до 19.09 19:00

1️⃣ Парк — 3: Аня, Дима, Боба
2️⃣ Кино — 5: Вика, Гоша, …
3️⃣ Дома — 1: Ева (снял выбор, 19:40)
```

### 4.3 Уведомления (TTL 48 ч, схлопываются)
```
📢 [Тренировка, пн 15.09] Берите перчатки и воду
⚠️ Изменение #12 «Тренировка»: начало → Вт 16.09 19:00
🔒 Запись закрыта: #12 «Тренировка». Придут 5, возможно 1.
⏰ Через 2 часа — «Тренировка» (придут 5)   ← reply на карточку
```
Напоминания — reply'ем на карточку, без TTL.

## 5. Голосование

- RSVP: yes/maybe/no + снятие; история → зачёркивания; дедуп по person.
- Опросы: строки `(poll, account, option, active)` — тумблеры; одиночный —
  переключение; «(снял выбор, 19:40)».
- Каждый голос → edit всех карточек (VK + TG), одно pending-задание на пост
  (свежая версия обновляет VM на месте).
- TG: голос только со слинковкой (иначе алерт); имена — из ВК; право голоса =
  линковка.
- Текстовый fallback (VK ЛС): reply на карточку.
- Двойное нажатие: dedup-кэш 2 с по (user, event_id, payload).

## 6. Объявления

- Глобальное: `[📢 Объявление]` → текст (+ медиа) → TTL-уведомления всем
  подписчикам (по настройке).
- По событию/опросу: панель `[⚙️ #id]` → `[📢 Объявление]` → текст →
  секция «📢 Объявления» в карточке (edit всех карточек) + TTL-уведомления.
- Изменение (`/edit`): та же механика, «⚠️ Изменение #id …».
- Медиа: фото/документы/голосовые — вложением; видео — ссылкой.

## 7. Обращения к админам

`[📩 Написать админам]` (активные VK + все TG) → релей сообщений админам в
VK ЛС («📩 [TG] Имя: текст»); ответ админа reply'ом возвращается участнику.
Без хранения истории.

## 8. Членство, админы, таймеры

- Членство: `groups.isMember` (кэш 10 мин); не член — «нет доступа»; академ
  (исключён из сообщества) → paused: карточки сняты, уведомление «📴»;
  вернулся → active + карточки + «👋 С возвращением».
- **Синк людей раз в час** (фоновый) + кнопка админа `[🔄 Синхронизация]`
  с отчётом об изменениях (админы +/-; подписки active↔paused).
- Админы: `groups.getMembers(filter=managers)` + ADMIN_VK_IDS.
- Событие: draft → active → closed (глава/авто в момент начала) ⇄ **reopen**
  (🔓 до момента начала; авто-закрытие срабатывает один раз — флаг
  `auto_closed`) → cancelled | finished (авто ends_at + 5 мин, финальная сводка в ЛС).
- Опрос: draft → active → closed (глава/авто по сроку) ⇄ **reopen** (пока срок
  не прошёл) | cancelled; без срока — до ручного закрытия.
- Напоминания (24 ч, 2 ч): reply на карточку (события — от начала, опросы — от
  closes_at).
- TTL-очистка уведомлений (`messages.delete` / `deleteMessage`).
- **Единая джоба актуализации**: `ensure_all_cards_for_user` + периодическая
  сверка — новые/вернувшиеся пользователи просто попадают в active, а джоба
  гарантирует, что карточки всех активных контентов у всех на месте и актуальны
  (триггеры: подписка, публикация, голос, линковка, синк; плюс тик 30 с).
- Лог завершённого — постом в сообщество; ночной бэкап БД (7 копий).

## 9. Модель данных

- `contents` — сквозной id (kind: event|poll); `events.id`/`polls.id` → contents.id.
- `posts`: content_type (event|poll|announcement), content_id, kind (dm_card|
  dm_notice), platform, chat_id, account_id, message_id, vm_hash, status
  (pending|ok|deleted|blocked), conflict; UNIQUE (content_type, content_id,
  kind, account_id).
- `poll_votes`: (poll_id, account_id, option_id) + active/updated_at/changes_count.
- `subscriptions`: active|paused|blocked|stopped + send_announcements +
  validated_at (академ = paused).
- `accounts`: mode (admin|member), tg_dm_notifications, tg_nick, person_id.
- `announcements`: content_type (event|poll|global) + content_id (NULL для global).
- `reminders`: content_type + content_id + at + done.
- `appeals` + `appeal_messages`: обращения (персист) и пересылки админам с
  пометкой «отвечено».
- `attendances`: отметка «кто реально пришёл» (event + person/account).
- `outbox`: op send|edit|delete, platform vk|tg, ретраи, idempotency_key.

## 11. Этапы реализации (выполнено)

0. Чистка моста/беседы/стены/канала; схема v2 (contents, posts, polls).
1. Членство через isMember; руководители-админы; режимы; клавиатуры; помощь.
2. События и опросы: fan-out в ЛС (VK-подписчики + слинкованные TG), живые
   карточки, сквозной id, текстовый fallback.
3. Управление: `/edit <id>`, компактные списки с `[⚙️ #id]`, панели, объявления
   (глобальные + секция + TTL + схлопывание).
4. TG ЛС: карточки/уведомления слинкованным, алерт, настройка уведомлений,
   обращения.
5. Надёжность: outbox (одно pending-задание на пост), сверка карточек,
   напоминания-reply, TTL-очистка, дедуп; тесты.

## 12. Принятые допущения

1. Имена в списках — из ВК; TG-голос только со слинковкой.
2. Опросы: до 10 вариантов; варианты после публикации не редактируются; без
   срока живёт до ручного закрытия; имена выбравших видны.
3. Создание командами: `/событие …`, `/опрос Вопрос` + варианты построчно
   (`[несколько]`, `[до …]`); `/edit <id> …`; визардов нет.
4. Уведомления объявлений/изменений — TTL 48 ч, схлопываются (edit последнего);
   напоминания — без TTL.
5. Обращения — персист в БД, ответ админа reply'ем; пометка «отвечено» остальным.
6. Режим админа хранится в БД и переживает рестарт.
7. БД пересоздаётся, alembic не заводим.

## 13. Деплой (Docker)

- `Dockerfile` (python:3.14-slim, non-root, HEALTHCHECK) + `compose.yaml`:
  volume `./data:/app/data`, `restart: unless-stopped`, лог-ротация 10 МБ × 3.
- SQLite: один процесс/инстанс, WAL, `busy_timeout`, checkpoint при SIGTERM,
  retention-чистка ежедневно (outbox 30 дн., посты 7 дн., обращения 90 дн.,
  напоминания 30 дн.) + VACUUM еженедельно, бэкапы 7 копий.
- Медиа/отчёты на диск не пишутся — всё в памяти (только БД и бэкапы в volume).
